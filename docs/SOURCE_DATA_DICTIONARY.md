# Figure source-data dictionary

Canonical source-data tables are generated by the workflow. Hand-edited source
tables are not permitted.

Every plotted quantitative row must retain, where applicable:

```text
panel_id
source_row_id
condition
genotype
biological_replicate
technical_replicate
x_value
x_unit
y_value
y_unit
direct_or_derived
included
exclusion_reason
summary_statistic
interval_or_error
statistical_comparison
p_value
adjusted_p_value
input_artifact_id
```

Additional proteomics fields include protein accession, gene, sector, molecular
mass, normalization state and ambiguity/exclusion rule. Additional model fields
include parameter-set ID, seed, timestep, flagellar mass fraction, rotation state,
solver status and normalization baseline.

Submission-friendly workbooks must be generated from these canonical tables with
one clearly named sheet per panel; the workbook is a derivative artifact, not the
source of truth.

## Source Data layout

`make source-data-available` writes three things:

| Output | Purpose |
|---|---|
| `build/source_data/submission/` | One Source Data file per figure. This is what we submit. |
| `build/source_data/deposit/` | The bundle for the DOI-bearing repository. |
| `build/source_data/Source_Data_revision_partial.xlsx` | The combined workbook. Internal use only. |

Nature Communications asks for one file per figure and accepts at most 30 MB per
file. The builder therefore emits twelve files:

```text
Source_Data_Figure_1 … Source_Data_Figure_7
Source_Data_Supplementary_Figure_1 … Source_Data_Supplementary_Figure_5
```

All twelve are `.xlsx` today; the largest is 7.7 MB. A figure ships as `.xlsx`
when the workbook stays within 30 MB. A larger figure ships as `.zip`, the
plain-text alternative the journal permits: one tab-separated `.txt` file per
table, all inside one folder. The builder measures the staged workbook and then
chooses; it never guesses.
`build/source_data/Source_Data_per_figure.manifest.json` records the format, the
size and the sha256 of every file.

## What one Source Data file contains

Each file stands on its own. A reviewer who opens one file alone gets:

- **README** — the figure name, the panels covered, the panels without tables and
  why, the unit convention, and the provenance path of every panel.
- **INDEX** — one row per table: `panel_id`, `sheet`, `table_name`, `origin`,
  `source_path`, `rows`, `columns`, `sha256`. `origin` is either `source file`
  or `derived in this build`, so no row claims a file that does not exist.
- **DATA_DICTIONARY** — one row per column: `panel_id`, `sheet`, `column`,
  `dtype`, `unit`, `source_path`. Every file carries the dictionary of its own
  columns. There is no separate companion file.
- one sheet, or one `.txt` member, per table.

In the ZIP form these become `README.txt`, `INDEX.txt` and
`DATA_DICTIONARY.txt`.

## Deposited tables

Some tables go to the DOI-bearing repository instead of the submitted Source
Data. `DEPOSITED_TABLE_PATHS` in `src/flagella_repro/source_workbook.py` names
them, one repository path per entry. They still pass the checksum gate; the
builder then routes them to `build/source_data/deposit/` and copies them byte
for byte, so their sha256 still matches the audited panel provenance.

Today the list holds the six simulated-trajectory tables of Supplementary
Figure 4 — 1,248,156 rows, 28.4 MB compressed. Marc approved this on
14 August 2026. They are raw model output rather than measurement, they are
exactly regenerable from the recorded seeds, and they were 57.6 % of the Source
Data volume.

`Source Data Supplementary Figure 4` keeps the six obstacle fields and adds two
tables derived from the trajectories during the build:

- `S4_condition_summary` — one row per panel: the model inputs the legend
  quotes, the three seeds, the obstacle geometry, and the population statistics
  of the drawn tracks.
- `S4_cell_summary` — one row per simulated cell: start and end position, net
  displacement, maximum excursion, track path length, mean track speed and final
  state.

A track path length is the sum of the sampled steps, so it includes diffusive
jitter and depends on the time step. It is not a swimming speed. Compare
`run_speed_um_s` with `median_track_speed_motile_um_s`, which counts motile
cells only.

The README of the Source Data file states what was deposited, why, where it will
live, how to regenerate it, and the sha256 of every deposited table. The deposit
bundle carries its own `README.txt` and a `MANIFEST.tsv` with the seeds and the
regeneration command.

## Units

The column name carries the unit:

| Suffix | Unit |
|---|---|
| `_um` | micrometre |
| `_um_s` | micrometre per second |
| `_ng_per_mL` | nanogram per millilitre |
| `_s` | second |
| `_per_h`, `_1_h` | per hour |
| `_percent` | percent |
| `_fraction` | dimensionless fraction, 0 to 1 |

`DATA_DICTIONARY` resolves this for every column in a `unit` column. An empty
`unit` means the column name states no unit. A `_ci95_low` or `_ci95_high`
column takes the unit of its base column. A `_min` or `_max` suffix is ambiguous
— it marks a minimum or a maximum in this repository, not minutes — so the
builder leaves those blank.

### One corrected unit: the anhydrotetracycline series

The anhydrotetracycline dose is ng/mL everywhere. Marc Erhardt confirmed this on
15 August 2026. The archived tables state two other units, and both are wrong.
Anhydrotetracycline is 427.45 g/mol, so 0.5 µM would be 214 ng/mL, far above the
range a PtetA promoter is induced over; ng/µL would be a thousandfold higher
still. Every figure since the July 2026 reference prints ng/mL.

Two figures read this series, and each restates the unit as the archived table
enters the build:

| Figure | Archived table says | Builder that restates it | Source Data now carries |
|---|---|---|---|
| 1C, 1D, 1E, 1H | column `AnTc_uM`, conditions `Ptet-flhDC 0.5 µM` | `analyses/figure_01/plotting.py` | `AnTc_ng_per_mL`, `Ptet-flhDC 0.5 ng/mL` |
| 6A | conditions `0.5 ng/ul AnTc` | `analyses/figure_06_revision/build_figure_06_revision.py` | `0.5 ng/mL AnTc` |

Every dose number is unchanged. Only the unit label changes.

The archived inputs keep the old labels. Every one of them lives under `data/`,
a read-only tree held outside git, and every one is pinned by sha256, so
rewriting one would break a check and would misreport what the archive holds:

| Archived input | Says | Pinned by |
|---|---|---|
| `data/processed/figure_01/F1_C/`, `F1_D/`, `F1_E/` | column `AnTc_uM` | `analyses/figure_01/migrate_legacy_tables.py`, against the immutable legacy bundle |
| `data/processed/figure_02/F2_A/per_curve.csv` | column `antc_uM`, `strain_display` values `Ptet (0.5 uM AnTc)` | `config/artifacts.csv` and the `F2_A` provenance |
| `data/processed/figure_06_revision/figure_06A_ptet_motility_measurements.csv` | conditions `0.5 ng/ul AnTc` | its builder, the `F6_A` provenance and `config/artifacts.csv` |

Read all of them as ng/mL. Nothing they say reaches a reader: the Figure 2A
builder takes the strain code, not `strain_display`, and no builder reads
`antc_uM`, so no Figure 2 output carries the wrong unit and none had to be
restated.

The retired pre-revision twins `data/processed/figure_04/` and
`data/source_data/figure_04/` hold the same Figure 6A measurements under the
July numbering and still say `ng/ul`. No builder, registry or provenance record
reads them. `docs/REPOSITORY_MAP.md` lists them as orphans. Read them as ng/mL
too.

## Table names

A table name is `<panel_id>_<role>`, for example `F1_C_distribution` or
`F7_D_unit_log_contrasts`. The name always carries the **current** panel ID.
Some producer scripts still write files under a retired panel name, such as
`data/source_data/figure_02/F2_F.csv.gz` for Figure 3C. The builder resolves the
name from the panel ID, so no retired name reaches a Source Data file.

Excel accepts at most 31 characters in a sheet name. A longer name is shortened
on a word boundary, never in the middle of a word. `INDEX.table_name` keeps the
full name.

## Duplicate tables

Four panels carry the same table twice: once under the pre-renumbering name in
`data/source_data/` and once under the current name in `build/source_data/`. The
builder keeps the current copy and drops the legacy copy, but only after it
proves that the current copy holds every row and every column of the legacy copy.
A legacy copy that is not fully contained survives, and the build records it.
`superseded_duplicates` in both manifests lists every drop.

## Checksum gate

A table enters the Source Data only when its sha256 matches the audited panel
provenance in `metadata/provenance/`. A mismatch aborts the build. This is why
the combined workbook is named `Source_Data_revision_partial.xlsx`: it covers the
panels that reproduce today, not all sixty.
